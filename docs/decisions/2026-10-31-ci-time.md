# Cutting CI's time per pull request (2026-10-31)

Several sessions open pull requests at once, and each heavy one costs about 300 runner-minutes over 47 jobs. Runners
became the bottleneck: jobs waited 20-65 minutes for an ubuntu-26.04 runner when five PRs ran at once.

## Measured (2026-10-31)

- A heavy PR: about 300 runner-minutes over 47 jobs. CI 34 jobs, about 150 minutes. Mutation 3 shards of about
  40 minutes each (about 126). Real world 8 jobs (about 19). CodeQL 2.
- Queuing per PR: 780 minutes (CI) and 260 minutes (real world).
- Runs: 41227553224 (CI, #664), 41227553145 (mutation), 41227553129 (real world), 41227020042 (CI, #662).

## The question

Which changes cut the runner time a pull request takes, without losing what CI checks?

### Choices

1. **Mutation on PRs runs only the entries the PR's files concern**: an entry whose File the PR changes, whose test
   class a changed test file declares, or that the PR adds to mutations.psd1. Every entry's Find is still checked (a
   stale entry fails), and the `mutation` required check still reports. All of them run nightly on main, in 3 shards,
   and a failed night opens an issue (or comments on the open one).
2. **A Directory.Build.props change that only moves ApiBaselineVersion / FrameReaderApiBaselineVersion is light**
   (tools/ci-changes.sh): `build` still packs and validates against the new baseline.
3. **Real world runs nightly only** (02:17 UTC, and on demand); on PRs "Real world passed" reports alone.
4. **Fewer parity jobs**: merge ci.yml's parity matrix (10 jobs, about 70 runner-minutes) into fewer jobs that keep the
   same comparisons, after finding out why it was split; or report that merging buys too little.

### Answer

**The owner chose all four** (2026-10-31, through the coordinating session).

## How

- 1: `Invoke-Mutations.ps1 -OnlyFiles <files> -Base <ref>` selects; `-Count` prints the selection's size, which
  mutation.yml's `changes` job turns into shards (one per 40 selected entries, at most 3, none when none; a PR that
  changes Invoke-Mutations.ps1 or mutation.yml runs them all). Light PRs
  (tools/ci-changes.sh) run their selection too, where they used to skip mutation: a FrameReader file ShotDetector
  doesn't run has guards of its own, and now costs only its own entries. Nightly at 03:41 UTC, with
  workflow_dispatch; tools/nightly-issue.sh files the failure.
- 2: tools/ci-changes.sh drops Directory.Build.props from the changed files when every changed line is one of the two
  baseline properties.
- 3: realworld.yml's jobs skip on pull_request with a job-level `if`, and its `changes` job is gone (nothing on a PR
  needs it). Branch protection requires only "Real world passed", so the per-matrix names a skipped matrix job doesn't
  report aren't missed, and the skipped jobs take no runner. A failed night opens an issue too.
- 4: investigated, left as is (owner, 2026-10-31): #135 split it for wall time; merging saves 2-4 runner-minutes,
  about 1% of a heavy PR.
