# FrameReader 2.24.0, never published (2026-11-06)

FrameReader 2.24.0's release PR merged on 2026-11-05, but its release run never reached the approval step: release
runs on main were cancelled while another waited for approval (GitHub keeps one pending run per concurrency group).
Before that run's version job ran again, the 2.25.0 release PR had merged, and release.yml released only each
product's newest version, so the run for 76038ab released 2.25.0 and left 2.24.0 untagged. Its CHANGELOG section
read as a release that nuget.org doesn't have. Since #759, release.yml fails on such a version instead of skipping it.

## Question

Asked with the multiple-choice prompt: "FrameReader 2.24.0 was never tagged or published; 2.25.0 (in today's release
run) contains its changes. What should happen to 2.24.0?" Options:

1. "Note it, don't publish (Recommended)": a line under 2.24.0's CHANGELOG heading saying it went out only inside
   2.25.0. Publishing it after 2.25.0 would add an older version nobody needs.
2. "Publish it late": tag its release commit (framereader-v2.24.0) by hand; release.yml builds and publishes it after
   its approval.
3. "Decide later".

## Answer

**Note it, don't publish.** The 2.24.0 section stays (it says what changed in that step), with a line under its
heading that it was never published and its changes first shipped in 2.25.0. No `framereader-v2.24.0` tag: once
2.25.0 is tagged, release.yml's check looks only at versions newer than the newest tag, so 2.24.0 never fails a run.
